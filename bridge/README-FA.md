# پل محلی WP Store Manager

این برنامه روی رایانهٔ متصل به LAN باشگاه اجرا می‌شود: لاگ‌های ZKTeco را می‌خواند، با HMAC به WordPress می‌فرستد و API محلی loopback و جریان SSE فراهم می‌کند. تب اتصال دستگاه، IPv4 خصوصی را در TCP پورت‌های 4370/515/9100/502 بررسی می‌کند و USB/COM را فهرست می‌کند؛ PyZK، Modbus، Serial، USB و پایگاه timezone از طریق وابستگی‌های اختیاری requirements نصب می‌شوند. رسید POS با ESC/POS و عرض ۸۰ میلی‌متر از طریق TCP/Serial/USB قابل ارسال است؛ آزمون‌های وضعیت ESC/POS/ZPL/TSPL جدا از چاپ‌اند و ZPL/TSPL در این نسخه فقط status probe دارند. Pair از پنل اپ با نشست مدیر، کد یک‌بارمصرف پنج‌دقیقه‌ای می‌سازد؛ نصب اولیه بدون REST URL، Access Key یا فایل پیکربندی دستی اجرا می‌شود. `bridge/install-windows.cmd` فقط همین Local Bridge کمکی را نصب می‌کند و نصب‌گر برنامهٔ دسکتاپ Tauri نیست. کاربر/رمز یا قالب خام اثرانگشت به WordPress فرستاده نمی‌شود. سازگاری هر مدل/Firmware عمومی نیست.

## پیش‌نیاز و نصب

- افزونهٔ WP Store Manager و WooCommerce فعال، سایت HTTPS، اینترنت برای نصب وابستگی‌های Python، و قرارگرفتن رایانهٔ پل و دستگاه‌ها در شبکهٔ محلی. Python 3.10 یا جدیدتر لازم است. نصاب Windows مسیر را از PATH، Python Launcher، رجیستری و پوشه‌های متداول پیدا می‌کند؛ اگر Python در CMD کار می‌کند ولی نصاب آن را نمی‌بیند، در wizard «انتخاب python.exe» را بزنید و فایل واقعی Python را انتخاب کنید. اگر Python نصب نیست، WinGet و سپس نصب‌گر رسمی Python 3.13.16 با بررسی SHA-256 تلاش می‌شود. نصب پل به دسترسی Administrator نیاز ندارد، مگر اینکه پوشهٔ انتخابی اجازهٔ نوشتن ندهد.
- پوشهٔ `bridge` را از ZIP استخراج کنید؛ هیچ فایلی را در پوشهٔ WordPress کپی نکنید.
  - **Windows (گرافیکی):** روی `install-windows.cmd` دوبار کلیک کنید. wizard محل نصب و در صورت نیاز مسیر `python.exe` را می‌گیرد؛ پس از نصب پل در پس‌زمینه و هنگام ورود Windows خودکار اجرا می‌شود و تا جفت‌سازی در حالت انتظار می‌ماند. اپ را روی همان رایانه باز کنید: «اتصال دستگاه» ← «جفت‌سازی امن با WordPress». سپس IP خصوصی، پورت TCP (پیش‌فرض ۴۳۷۰) و رمز ترمینال را در پنل وارد و آزمون کنید. میانبر «Local Bridge Settings» برای عیب‌یابی/سازگاری CLI قدیمی باقی است؛ نام فایل میانبر عمداً ASCII است تا در Windows PowerShell 5.1 روی تنظیمات منطقه‌ای مختلف خطای ذخیرهٔ Shortcut رخ ندهد. برای نصب تازه لازم نیست.
  - **Linux:** `chmod +x install-linux.sh && ./install-linux.sh`. اگر systemd user در دسترس باشد سرویس نصب و فعال می‌شود؛ در غیر این صورت پل فوراً در پس‌زمینه اجرا می‌شود. اپ باید روی همان رایانه باز باشد تا Pair امن و افزودن IP از پنل انجام شود.
- Pair فقط با نشست مدیر WordPress انجام می‌شود؛ کلید محلی تصادفی پس از Pair به مرورگر مجاز تحویل می‌شود و در فایل فرانت‌اند ثابت نیست. برای تطبیق لاگ با ورزشکار، شناسهٔ ترمینال باید در پروندهٔ عضو با `device_user_id` یکسان باشد.
- Pair یک دستگاه پل تازه با مجوز محدود `club.bridge` در WordPress ثبت می‌کند؛ لازم نیست برای پل دسترسی‌های دیگر را روشن کنید. از **مدیر فروشگاه ← دستگاه‌ها** می‌توانید نشست همان دستگاه را در صورت نیاز قطع/لغو کنید.
- برای آزمون خط فروشگاهِ ذخیره‌شده: `python wsm_local_bridge.py test-store`. برای آزمون واقعی دستگاه، اتصال مستقیم و خواندن گزارش تردد: `python wsm_local_bridge.py test-zk`؛ این آزمون اطلاعات را ذخیره یا دستگاه را تغییر نمی‌دهد. در Windows از دکمه‌های آزمون داخل پنجرهٔ تنظیمات استفاده کنید. برای افزودن/جایگزینی دستی دستگاه: `python wsm_local_bridge.py add-zk`. IP خصوصی، پورت، نام و جهت را وارد کنید. جهت پیش‌فرض ثابت است؛ رابط اپ می‌تواند فقط با نگاشت صریحی مثل `0=in,1=out` فیلد `punch` یا `status` را تفسیر کند. معنای این کدها بین مدل/Firmwareها یکسان نیست؛ نگاشت را از دفترچهٔ همان دستگاه تأیید کنید و در صورت نامشخص‌بودن از حالت ثابت استفاده کنید.

## رفع خطای وابستگی‌های سخت‌افزاری در Windows

- بسته‌های `pyzk`، `pymodbus`، `pyserial`، `pyusb` و `tzdata` با pip داخل محیط مجازی `.venv` در پوشهٔ نصب می‌آیند؛ درایور COM یا درایور سازندهٔ دستگاه نصب نمی‌شود. `pyserial` و `pyusb` کتابخانه‌اند؛ اگر دستگاه USB/Serial به درایور سازنده یا WinUSB نیاز داشته باشد، آن را جداگانه از سازندهٔ سخت‌افزار نصب کنید.
- اگر نصب‌گر گفت «بخشی از وابستگی‌ها نصب نشد»، از دکمهٔ «گزارش نصب» استفاده کنید یا `%TEMP%\wsm-bridge-install.log` را باز کنید. گزارش شامل نام بسته و خروجی واقعی pip است؛ گزارش نصب پیشین در `%TEMP%\wsm-bridge-install-*.log` نگه داشته می‌شود.
- خطای timeout، DNS، SSL یا proxy معمولاً به دسترسی شبکه/PyPI مربوط است و با Administrator رفع نمی‌شود؛ اتصال اینترنت، پراکسی یا محدودیت فایروال را بررسی و دوباره امتحان کنید. نصب‌گر اکنون برای اختلال گذرا چند بار تلاش می‌کند.
- نصب پیش‌فرض در `%LOCALAPPDATA%\Programs\WP Store Manager Bridge` دسترسی Administrator نمی‌خواهد. فقط اگر گزارش `Access denied`/`Permission denied` نشان داد و پوشهٔ محافظت‌شده‌ای انتخاب شده، از مسیر پیش‌فرض استفاده کنید یا همان‌طور که wizard راهنمایی می‌کند با **Run as Administrator** نصب را اجرا کنید.
- فرمان نصب دستی که wizard نشان می‌دهد از همان Python محیط مجازی و فایل `requirements.txt` استفاده می‌کند؛ خروجی کامل را از گزارش بررسی کنید.

## فرمان‌ها

- `python wsm_local_bridge.py run` — API محلی loopback روی پورت ۸۷۶۵ و همگام‌سازی دوره‌ای را اجرا می‌کند؛ بدون config می‌ماند تا از پنل اپ Pair شود. تردد معمول هر ۴۵ ثانیه بررسی می‌شود و پس از opt-in گیت، چرخهٔ پل به ۱ ثانیه کاهش می‌یابد؛ فهرست دسترسی هر ۵ دقیقه، کاربران هر ۳۰ دقیقه و ساعت هر ۶ ساعت بررسی می‌شوند. این polling/REST تأخیر کامل زیر ۱۰۰ms را تضمین نمی‌کند.
- `python wsm_local_bridge.py setup` و `add-zk` — مسیر CLI قدیمی/پیشرفته؛ برای جفت‌سازی تازه لازم نیست. در نسخهٔ فعلی WordPress، Access Key فقط ورود اولیه را آغاز می‌کند و نشست پل نمی‌سازد؛ جفت‌سازی تازه باید از اپ دسکتاپ، با نشست مدیر و مسیر «اتصال دستگاه ← جفت‌سازی امن با WordPress» انجام شود.
- `python wsm_local_bridge.py test-store` — آزمون نشست و امضای REST ذخیره‌شده؛ `test-zk` اتصال واقعی LAN و خواندن گزارش را فقط‌خوانی می‌آزماید.
- `python wsm_local_bridge.py local-api-info` — ابزار عیب‌یابی محلی برای نمایش کلید API تصادفی؛ پنل اپ پس از Pair کلید را خودکار می‌گیرد و نیازی به این فرمان ندارد. هرگز کلید را در گزارش/کد عمومی ذخیره نکنید.

تنظیمات و شناسه‌های تکراری‌زدایی در `%LOCALAPPDATA%\WPStoreManagerBridge\config.json` در Windows یا `~/.config/wp-store-manager-bridge/config.json` در Linux ذخیره می‌شوند. این فایل شامل توکن امضا و رمز ارتباط دستگاه است؛ آن را عمومی نکنید، در Git قرار ندهید و فقط به کاربر سیستم مجاز دسترسی دهید. برای تغییر پیوند پل، جفت‌سازی امن را از اپ دسکتاپ دوباره انجام دهید و دستگاه قبلی را از پیشخوان لغو کنید؛ Access Key برای جفت‌سازی تازه استفاده نمی‌شود.

## API محلی مدیریت سخت‌افزار

هنگام اجرای `run`، سرویس فقط روی `127.0.0.1:8765` گوش می‌دهد و از LAN/اینترنت در دسترس نیست. به‌جز `POST /api/v1/pair` که برای bootstrap به Pair token کوتاه‌عمر، Host loopback و Origin معتبر نیاز دارد، مسیرها کلید تصادفی `X-WSM-Local-Key` و Origin مجاز همان فروشگاه را می‌خواهند. `GET /api/v1/events/stream` جریان SSE امضاشدهٔ محلی است؛ preflight مرورگر، از جمله Local Network، پاسخ داده می‌شود. کلید را در کد عمومی یا WordPress ذخیره نکنید. Pair از PWA روی Origin HTTPS فروشگاه و از پوستهٔ Windows Tauri روی Origin محلی `http://tauri.localhost` پشتیبانی می‌شود؛ در هر دو مسیر، Pair token در WordPress به Origin واقعی REST API و مدیر احراز‌شده مقید است. Workflow ساخت، باینری sidecar و DLLهای لازم را بررسی می‌کند؛ اجرای نصب‌کننده روی Surface Pro 5 و آزمون سخت‌افزار واقعی در این محیط انجام نشده است.

مسیرهای پایه: `POST /api/v1/pair`, `GET /api/v1/events/stream`, `GET /api/v1/health`, `GET /api/v1/capabilities`, `POST /api/v1/mock/test` (شبیه‌سازی بی‌اثر؛ هیچ سخت‌افزار، WordPress یا تنظیم دستگاه را تغییر نمی‌دهد), `GET /api/v1/discover` (اسکن TCP فقط‌خواندنی در IPv4 /24 خصوصی همراه USB/Serial), `GET /api/v1/serial/ports`, `POST /api/v1/serial/identify`, `POST /api/v1/barcode/hid`, `GET/POST /api/v1/devices`, `GET/PUT/DELETE /api/v1/devices/{id}`, `GET /api/v1/devices/{id}/status`, `POST /api/v1/devices/{id}/gate/test` (فقط Read Coils), `GET/POST /api/v1/devices/{id}/users`, `POST /api/v1/devices/{id}/users/sync`, `PUT/DELETE /api/v1/devices/{id}/users/{uid}`, `GET /api/v1/devices/{id}/users/{uid}/fingerprints`, `POST /api/v1/devices/{id}/users/{uid}/fingerprints/enroll`, `DELETE /api/v1/devices/{id}/users/{uid}/fingerprints/{finger_id}`, `POST /api/v1/devices/{id}/time/sync`, `POST /api/v1/devices/{id}/attendance/sync`, `DELETE /api/v1/devices/{id}/attendance`. کاربران WordPress فقط ID و نام می‌گیرند و خودکار حذف نمی‌شوند. پاک‌کردن لاگ فقط با `confirm:true` و `sync_before_clear:true` انجام می‌شود.

در مرکز اتصال دستگاه، «حالت شبیه‌ساز» سناریوهای ESC/POS، وضعیت لیبل‌زن، اسکن HID/Serial/RFID، Read Coils، مجوز مجاز/ردشده و fallback چاپ را بدون دستگاه واقعی اجرا می‌کند. هر نتیجه با `simulated=true` و `side_effects=false` مشخص است؛ این آزمون‌ها اثبات سازگاری مدل یا چاپ فیزیکی نیستند.

پاسخ فهرست کاربران رمز دستگاه را افشا نمی‌کند؛ ارسال رمز فقط هنگام ثبت/ویرایش است. برای اثرانگشت، endpoint enrollment از کاربر می‌خواهد انگشت را روی ترمینال بگذارد؛ این قابلیت به مدل/Firmware وابسته است و ممکن است در بعضی ZK8ها کار نکند. عملیات واقعی را روی دستگاه خود آزمایش کنید.

## محدودیت مهم کنترل گیت

سازگاری شبکه‌ای PyZK، چهره‌خوان REST و پروتکل‌های پرینتر/گیت به مدل، Firmware و تنظیمات وابسته است. آزمون‌های وضعیت ESC/POS، ZPL و TSPL فقط درخواست غیرچاپیِ پروتکل صریحاً انتخاب‌شده می‌فرستند؛ اما مسیر چاپ رسید POS جداست: raster عرض ۵۷۶px/۸۰mm را با ESC/POS از پل به پرینتر TCP، Serial یا USB می‌فرستد. پاسخ «ارسال شد» فقط نوشتن/ارسال بایت‌ها را تأیید می‌کند و تضمین چاپ فیزیکی نیست. ZPL/TSPL در این نسخه فقط status probe دارند و چاپ لیبل ندارند. اسکن خودکار فقط reachability پورت را می‌یابد و پروتکل چاپ را تعیین نمی‌کند؛ USB/Serial بودن پورت نیز به‌تنهایی سازگاری مدل را اثبات نمی‌کند. اگر خطا پیش از ارسال job قطعی باشد، رابط POS پنجرهٔ چاپ مرورگر/درایور سیستم‌عامل را به‌عنوان fallback باز می‌کند؛ از همان پنجره می‌توان در صورت پشتیبانی سیستم‌عامل «ذخیره به PDF» را انتخاب کرد. اگر ارتباط پس از آغاز ارسال قطع شود و نتیجه نامشخص بماند، fallback خودکار متوقف می‌شود تا رسید تکراری چاپ نشود؛ وضعیت چاپگر را بررسی کنید و سپس در صورت نیاز دستی چاپ مجدد کنید. Web Serial برای بارکدخوان سریال/COM به‌صورت اختیاری در فرم POS اضافه شده است: فقط در مرورگر سازگار و secure context، با کلیک کاربر برای انتخاب پورت و baud rate پیش‌فرض ۹۶۰۰ (قابل‌تغییر). اگر اسکنر terminator نفرستد، سکون ۴۵۰ms پایان اسکن فرض می‌شود؛ دادهٔ ناقص هنگام قطع جریان دور ریخته می‌شود و پاسخ جست‌وجوی دیررس پس از توقف/ترک POS به فاکتور افزوده نمی‌شود. اگر سیستم‌عامل اسکنر را به‌صورت COM ارائه نکند، از پل محلی استفاده کنید. WebUSB برای چاپگر و WebHID برای دستگاه‌ها در این نسخه یکپارچه نشده‌اند؛ QZ Tray هم بدون مسیر امضای امن/گواهی فعال نیست. ADMS/Push عمومی پشت NAT به endpoint عمومی HTTPS در WordPress نیاز دارد که در این محدوده پیاده‌سازی نشده است؛ بنابراین این نسخه دریافت‌کنندهٔ عمومی ADMS نیست. RFID/NFC HID و بارکد HID معمولاً مانند کیبورد عمل می‌کنند و به فیلد فوکوس‌دار نیاز دارند؛ دکمهٔ بازیابی فوکوس در POS وجود دارد. آزمون HID در مرکز سخت‌افزار فقط طول/وجود نمونه را ثبت می‌کند؛ در POS، کد HID یا Serial برای جست‌وجوی محصول استفاده می‌شود و به‌عنوان تردد/قالب اثرانگشت ذخیره نمی‌شود. RS-232/بلوتوث SPP به COM واقعی/مجازی سیستم‌عامل وابسته است.

بازشدن خودکار گیت به‌طور پیش‌فرض خاموش است. فقط Modbus TCP/RTU با opt-in صریح مدیر، رویداد تازه و پاسخ کامل WordPress با `accepted=true`، `duplicate=false`، `decision=allowed` و تطبیق دقیق `event_id` و `device_user_id` مجاز به ارسال پالس کویل است؛ پاسخ ناقص/قدیمی یا نامنطبق fail-closed می‌شود و بعد از پالس فرمان خاموشی نیز ارسال می‌شود. این رفتار، کنترل عمومی dry-contact/SDK همهٔ سازندگان نیست. گردش فعلی از polling و REST عبور می‌کند: زمان فرمان محلی اندازه‌گیری می‌شود، اما تأخیر کامل اثرانگشت تا گیت زیر ۱۰۰ms تضمین‌پذیر نیست. اتصال، سیم‌بندی، نوع رله/کویل، جهت ورود/خروج، fail-safe بودن و عملکرد هر مدل باید حضوری توسط نصاب آزمایش شود؛ پورت دستگاه را روی اینترنت Port-forward نکنید.

چاپ POS ابتدا با رسید ESC/POS از طریق Local Bridge انجام می‌شود؛ وقتی خطا پیش از ارسال job قطعی باشد، رابط به پنجرهٔ چاپ مرورگر/درایور سیستم‌عامل fallback می‌کند و کاربر می‌تواند، اگر درایور فراهم کند، PDF را ذخیره کند. اگر job احتمالاً ارسال شده ولی پاسخ گم شده باشد، fallback خودکار متوقف می‌شود تا رسید تکراری چاپ نشود؛ پس از بررسی چاپگر، چاپ مجدد دستی ممکن است. QZ Tray در این نسخه پیکربندی/گواهی امضاشده ندارد و استفاده از آن فعال نیست. اتصال کارتخوان به دریافت خودکار نتیجهٔ تراکنش، بدون مشخص‌بودن شرکت پرداخت، کشور، مدل دستگاه و SDK/قرارداد پذیرندگی امکان‌پذیر نیست؛ ثبت «کارتخوان» در دفتر دریافت، به‌تنهایی تراکنش را شارژ یا تأیید نمی‌کند.
