# ساخت APK سبک از PWA با HTML-to-APK

این پوشه برای اجرای وب‌اپ در یک WebView آماده است؛ APK امضاشده یا Android SDK داخل ZIP قرار نگرفته، چون خروجی نهایی به ابزار/کلید امضای صاحب سایت وابسته است.

## تنظیم پیشنهادی در ابزار HTML-to-APK

1. افزونه را در WordPress نصب و فعال کنید و صفحهٔ وب‌اپ را در مرورگر باز کنید. نشانی دقیق را از دکمهٔ اجرای اپ در پیشخوان بردارید؛ معمولاً شبیه `https://example.com/wp-content/plugins/wp-store-manager/wsm-app/` است، اما مسیر واقعی سایت شما ملاک است.
2. در ابزار، حالت **Website URL / WebView** را انتخاب و همین نشانی HTTPS را به‌عنوان Start/Home URL بدهید. از حالت `file://` یا بارگذاری تکی `index.html` استفاده نکنید: در آن حالت origin سایت و مسیر REST API معلوم نیست و ورود/درخواست‌های امضاشده درست کار نمی‌کنند.
3. JavaScript و **DOM Storage / localStorage** را روشن کنید؛ ناوبری و درخواست‌های HTTPS همان دامنه را مجاز بگذارید. HTTPS اجباری بماند و Mixed Content، دسترسی فایل‌های ناامن و cleartext HTTP خاموش باشد.
4. نمایش standalone اختیاری است؛ جهت را روی «خودکار/پیروی از دستگاه» بگذارید تا Android چرخش صفحه را مدیریت کند. دوربین، مخاطبین، موقعیت مکانی، میکروفون، دسترسی فایل گسترده، سرویس پس‌زمینه و دسترسی سخت‌افزاری خاص لازم نیست. بارکدخوان USB-HID در صورت پشتیبانی دستگاه مانند صفحه‌کلید کار می‌کند؛ چاپ همچنان به WebView/سیستم‌عامل و درایور چاپ وابسته است.
5. APK را با کلید امضای خودتان در ابزار انتخابی بسازید؛ کلید امضا را داخل ZIP افزونه یا در سرویس ناشناس بارگذاری نکنید. قبل از انتشار، اتصال، خروج، مجوزهای مستقل باشگاه، نمایش RTL و به‌روزرسانی PWA را روی گوشی واقعی بررسی کنید.

## نکتهٔ سخت‌افزار

ساخت APK، پل محلی رایانه را جایگزین نمی‌کند. همگام‌سازی ZKTeco در این بسته از `bridge/` روی Windows/Linux و شبکهٔ خصوصی باشگاه انجام می‌شود. کنترل گیت/رله، NFC یا حسگر تلفن عمداً فعال نشده و به مدل، SDK و آزمون سخت‌افزار نیاز دارد. اپ موبایل برای استفادهٔ عادی به پل یا مجوزهای سخت‌افزار وابسته نیست.
